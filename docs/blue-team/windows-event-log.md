# Windows 이벤트 로그

---

## 윈도우 이벤트 로그란

Windows는 시스템에서 일어나는 일을 **이벤트(Event)** 단위로 기록한다.

크게 세 가지가 있다.

| 로그(채널) | 담는 내용 |
| --- | --- |
| Security | 로그온/로그오프, 권한 사용, 계정/정책 변경 등 **보안 감사** 이벤트 |
| System | 드라이버, 서비스 시작/중지, 시스템 부팅 등 OS 동작 |
| Application | 응용 프로그램이 남기는 로그 |

이 외에 Sysmon, Powershell 등은 Applications and Services Logs 아래에 별도 채널로 기록된다.

로그는 로컬에서는 이벤트 뷰어(eventvwr.msc)나 wevtutil 명령으로 볼 수 있다. 

엔드포인트마다 흩어진 로그를 한곳에서 보기 위해서 SIEM(Splunk, ELK 등)를 사용한다.

> 로그온 : 일반적으로 말하는 로그인과 같은 의미. 계정 인증이 성공해 windows 세션이 생성된 것

---

## 이벤트의 구조

각 이벤트에는 다음 정보들이 포함된다.

- Event ID — 이벤트의 종류를 나타내는 번호 (예: `4625` = 로그온 실패)
- Source / Channel — 어느 로그에서 나왔는지
- 계정 정보 — 어느 계정인지
- 세부 필드 — 출발지 IP, 프로세스 이름, 로그온 타입 등

## 핵심 Security 이벤트 ID

### 인증 / 로그온

| Event ID | 의미 | 세부 사항 |
| --- | --- | --- |
| 4624 | 로그온 성공 | 누가, 어디서, 어떤 방식(로그온 타입)으로 들어왔나 |
| 4625 | 로그온 실패 | 다량 발생 시 브루트포스 의심 |
| 4634 / 4647 | 로그오프 | 세션 추적 |
| 4648 | 다른 계정 정보로 실행/접속 | `runas`, 횡적 이동에서 자주 보임 |
| 4672 | 특수 권한(관리자) 부여 로그온 | 관리자 권한 세션 생성 — 4624와 함께 보면 "관리자가 로그온함" |
| 4740 | 계정 잠김(Lockout) | 실패 누적의 결과 |

Logon Type은 어떤 방식으로 로그인/접속했는지를 나타내고 4624/4625를 해석할 때 핵심이다.

| 타입 | 쉽게 말하면 | 예시 |
| --- | --- | --- |
| 2 | PC 앞에서 직접 로그인 | 키보드로 비밀번호 치고 Windows에 들어감 |
| 3 | 네트워크로 접근 | 파일 공유, SMB, 다른 PC/서버 접근 |
| 4 | 예약 작업이 실행됨 | 작업 스케줄러가 특정 계정으로 실행 |
| 5 | 서비스가 실행됨 | Windows 서비스가 서비스 계정으로 실행 |
| 7 | 잠금 해제 | 잠긴 화면을 비밀번호로 풀었을 때 |
| 10 | 원격 데스크톱 접속 | RDP로 다른 PC에 접속 |
| 11 | 저장된 로그인 정보 사용 | 도메인 서버 연결이 안 돼도 예전 정보로 로그인 |


### 계정 / 권한 변경

| Event ID | 의미 |
| --- | --- |
| 4720 | 사용자 계정 생성 |
| 4722 / 4725 | 계정 활성화 / 비활성화 |
| 4724 | 비밀번호 재설정 시도 |
| 4726 | 계정 삭제 |
| 4728 / 4732 / 4756 | 보안 그룹에 멤버 추가 (특히 4732 = 로컬 Administrators 그룹 추가) |

> 공격자가 침투 후 지속성을 확보할 때 계정을 만들고(4720) 관리자 그룹에 넣는(4732) 패턴이 전형적이다.

### 프로세스 / 실행

| Event ID | 의미 |
| --- | --- |
| 4688 | 프로세스 생성 — 무엇이 실행됐는지 |
| 4689 | 프로세스 종료 |

### 흔적 제거 / 정책 변경

| Event ID | 의미 |
| --- | --- |
| 1102 | 감사 로그가 삭제됨 — 공격자가 흔적을 지우는 행위 |
| 4719 | 시스템 감사 정책 변경 — 탐지를 무력화하려는 시도일 수 있음 |

## 공격 시나리오로 보는 이벤트

같은 이벤트도 묶어서 볼 때 의미가 생긴다. SOC 분석은 단일 이벤트가 아니라 시퀀스(흐름)를 본다.

| 공격 행위 | 남는 이벤트 흐름 |
| --- | --- |
| 무차별 대입 Brute Force | `4625` 다량 → 성공 시 `4624` / 잠금 시 `4740` |
| 횡적 이동 / 원격 인증 | `4624` (타입 3) + `4672` + `4648` |
| 권한 상승 | `4672`, 의심 프로세스 `4688` |
| 지속성 확보 | `4720`(계정 생성) → `4732`(관리자 그룹 추가) → `4698`(예약 작업 생성) |
| 흔적 제거 | `1102`(로그 삭제), `4719`(감사 정책 변경) |

## 예시 SPL

수집된 Windows 이벤트 로그를 Splunk에서 검색하는 기본 패턴이다. (필드 이름은 sourcetype, 필드 추출 설정에 따라 다를 수 있다.)

**로그온 실패가 많은 계정/출발지 — 브루트포스 후보**

```spl
index=wineventlog EventCode=4625
| stats count by Account_Name, Source_Network_Address
| where count > 10
| sort - count
```

**실패가 누적된 뒤 성공한 계정 — 브루트포스 성공 의심**

```spl
index=wineventlog (EventCode=4625 OR EventCode=4624)
| stats count(eval(EventCode=4625)) AS fail
        count(eval(EventCode=4624)) AS success
        by Account_Name, Source_Network_Address
| where fail > 10 AND success > 0
```

**감사 로그 삭제 탐지 — 발생하면 즉시 확인**

```spl
index=wineventlog EventCode=1102
| table _time, host, Account_Name
```

**의심스러운 프로세스 실행 (4688)**

```spl
index=wineventlog EventCode=4688
  (New_Process_Name="*\\powershell.exe" OR New_Process_Name="*\\cmd.exe"
   OR New_Process_Name="*\\whoami.exe" OR New_Process_Name="*\\net.exe")
| table _time, host, Account_Name, New_Process_Name, Process_Command_Line
```

## 오탐을 줄이는 방법

- 적절한 임계치 설정 — 실패 1~2회는 오타일 가능성이 높고 의미 있는 로그는 단시간에 다량 같은 패턴이다.
- 단일 이벤트가 아니라 흐름을 보기 — 4625 하나가 아니라 `4625 다량 -> 4624` 처럼 흐름으로 본다.
- 출발지 IP가 내부인지 외부인지, 발생 시간이 업무 시간인지 새벽인지, 대상 계정이 일반 계정인지 관리자 계정인지 같은 정보를 함께 봐야 정탐과 오탐을 구분할 수 있다.

## Windows 기본 로그의 한계

네트워크 연결, 파일 생성, 프로세스의 부모-자식 관계는 Windows 기본 로그로는 보기 불편하다.
이 한계를 극복하기 위해 사용하는 게 Sysmon이다.
