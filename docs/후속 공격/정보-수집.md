# 정보 수집
<br>

호스트 안에서 수집된 호스트의 정보를 바탕으로 후속 공격 진행

- 나는 누구인가
> 유저 이름, 그룹 이름, 권한 등
- 나는 어디에 있는가
> 호스트 이름, 운영체제 버전, IP주소, 네트워크, Route, ARP 등
- 호스트에는 뭐가 있는가
> 파일, 서비스, 프로세스 등
- 나는 어떤 권한을 갖고 있는가
> RWX<br>
> 파일, 서비스, 프로세스, 작업 스케줄을 실행할 수 있는 권한이 있는가

## 정보 수집 종류

- 하드코딩 된 계정 정보
- 소프트웨어 로컬 권한 상승 취약점
- 내부 관리자 패널 노출 정보
- 환경 변수
- 잘못된 파일 권한
- 잘못된 SUID 권한
- 잘못된 유저 및 그룹 권한
- 잘못된 sudo 권한
- 잘못된 서비스 권한
- 하드코딩 된 설정 파일
- 작업 스케줄
- 커널 익스플로잇
등

---


팁
- 기본 상태 호스트의 기본 속성(유저, 파일, 디렉토리, 서비스, 프로세스, 애플리케이션/소프트웨어)<br>
> 타겟 시스템에 맞는 OS를 설치 후 비교<br>
> 우분투 22.04, 윈도우11, 윈도우 서버 등
- 디폴트 상태와 다른 속성이 있다면 어떻게 악용할 수 있는지
- 목표를 정하고 행동

## 컨테이너/도커/쿠버네티스 환경 확인

| cat /proc/self/cgroup | 도커 컨테이너나 쿠버네티스에서 실행 중인 프로세스는 특정 cgroup에 속하게 된다. 이 정보는 /proc/self/cgroup 파일에 표시되고 해당 정보를 확인하면 프로세스가 어떤 컨테이너 환경에서 실행 중인지 파악 가능함 |
|:--------:|:------------------------------------------------------:|
| ls -ahl /.dockerenv | Docker 컨테이너에서 실행 중인지 여부를 확인하는 데 사용됨. Docker 컨테이너에서 실행 중이라면 디렉토리에 .dockerenv 파일이 존재함 |
